# AGENTS.md

Instructions for AI coding agents working in this repository.

## Rules

1. **Never run git commands that change anything, unless the user explicitly asks for that exact action in their current message.** This includes `add`, `commit`, `amend`, `reset`, `checkout`/`switch`, `stash`, `rebase`, `merge`, `tag`, `push` and branch create/delete. It also covers anything that changes GitHub: `gh pr create/merge/close`, `gh api` writes, releases and repository settings.
   - Read-only commands are fine: `git status`, `git log`, `git diff`, `git show`, `git branch --list`, `gh pr view`.
   - A question about the release flow ("then we push and tag?") is a question, not an instruction.
   - Leave changes uncommitted in the working tree. The maintainer reviews, commits and pushes.
2. **No AI attribution.** Never add `Co-Authored-By`, "Generated with…" or similar lines to commits, PRs, tags or files.
3. **Pushing a `v*` tag deploys the live site.** Never create or push tags.
4. If an action is blocked or fails, stop and report it. Don't substitute a different or more destructive action.

## Project

- Jekyll static site for djabstraction.com (DJ mixes plus a podcast feed). It's served from S3 behind CloudFront.
- Posts: `_posts/`. Mix pages use `layout: mix` with `tracklist`, `mp3streamurl`, `downloadurl` and `duration` front matter.
- Feeds:
  - `feed/podcast.xml` is a **hand-written Liquid template** for the podcast RSS. Changes to it, or to post front matter, can break podcast apps.
  - `feed.xml` is generated by `jekyll-feed`.
- Custom Liquid filter: `_plugins/time_to_seconds.rb` (`time_seconds`).
- `assets/vendor/` holds vendored Bootstrap, Font Awesome and Clean Blog. Don't edit them.
- `docs/plans/` holds design and refactor plans. `docs/` is excluded from the built site.

## Build

The supported environment is WSL2 Ubuntu. See `README.md` for setup.

```bash
bundle install
bundle exec jekyll build                           # output in _site/
bundle exec jekyll serve --force_polling           # http://localhost:4000
bundle exec jekyll serve --force_polling --future  # include future-dated posts
```

- Ruby version: `.ruby-version`. Bundler version: `BUNDLED WITH` in `Gemfile.lock`.
- When changing gems, keep `Gemfile.lock` platforms (`ruby`, `x86_64-linux`, `x86_64-linux-gnu`, `x64-mingw-ucrt`) and don't pick up prerelease Bundler versions.
- Before handing back changes that affect output, run a build and then `bundle exec ruby .github/scripts/validate-feeds.rb`. For template or front-matter changes, also compare `_site/feed/podcast.xml` and `_site/feed.xml` with the previous output.

## CI/CD

- `.github/workflows/build.yml` builds PRs and pushes to `main`, then validates the feeds. It never deploys.
- `.github/workflows/deploy.yml` deploys only from `v*` tags on commits in `main`: Jekyll build, feed validation, `aws s3 sync --delete`, then a CloudFront invalidation. A feed validation failure stops the deploy before anything is uploaded.
- `.github/scripts/validate-feeds.rb` checks that both feeds are well-formed XML and that every podcast episode has the required fields with valid values (enclosure URL and length, guid, pubDate, duration, episode number, artwork, chapter times). When adding a field to the podcast template, add a check here too.
- `_config.yml` sets `timezone: Europe/London`, which controls post dates and when future-dated posts appear.
